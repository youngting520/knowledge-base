## 把产品说明变成可旋转、可拆解的 3D 网页

<a name="work-7710668566689405267"></a>

**学习场景**　要向读者展示产品内部结构或工作流程时。

- 提供一张产品图，先让 AI 列出结构层级、零件、材料和关键参数。用产品规格表核对清单。
- 把主体、拆解层级、流程动画、视觉风格、交互和技术要求写进提示词，让 AI 用 Three.js 生成单文件网页。
- 让另一个 AI 对照清单复检，重点看遗漏的部件、过近的机位和过强的光照。

## 把 Blender 模型放进 Three.js 网页

<a name="work-7707177332607519907"></a>

**学习场景**　模型导入网页后尺寸不对、材质失真或一片黑。

- Blender 用米作单位，对模型应用旋转和缩放。场景里只保留要交付的模型和动画。
- 复杂的程序化材质或 Eevee 专属效果可先烘焙成颜色、法线、金属度和粗糙度贴图，接入原理化 BSDF 后再导出 GLB。
- 网页用 GLTFLoader 载入。遇到黑模先查场景灯光和环境贴图，再核对材质通道。

## 区分提示词、上下文与运行控制

<a name="work-7707287096683154738"></a>

**学习场景**　给智能体写了很长的要求，却分不清问题出在哪一层时。

- 提示词描述这次要做的事。示例把任务拆成角色、目标、约束、输入输出示例和交付格式。
- 上下文工程安排模型实际看到的资料。演示把稳定规则放前面，再给当前任务和相关资料，在关键动作前重申约束。
- 运行控制决定能调用什么、在哪一步停下。规划旅行时可授权查航班和算预算，把付款和提交身份信息留给人工确认。

## 把 Agent 的规划、工具和记忆分开设计

<a name="work-7694528981122551066"></a>

**学习场景**　准备让智能体承担一个需要连续操作的任务时。

- 先定行动边界。按事情的影响和复杂程度，区分它能自行推进的步骤与必须让用户确认的步骤。
- 再选规划方式。路径固定的工作可走流水线，需要继续搜集线索再决定下一步的工作适合探索式规划。
- 把具体动作交给工具层编排，区分当前任务所需的短期记忆与需要跨任务保留的长期记忆。过程应让人看得见，任务卡住也要有停止条件。

## 在 GitHub 上找适合自己电脑的开源工具

<a name="work-7706798895526907171"></a>

**学习场景**　知道工作需求，想从开源项目里选一个可以上手的工具时。

- 知道项目名就精准搜索，不知道名字就按用途搜。想系统浏览某个方向，可试“Awesome 加主题词”。
- 先读项目简介确认用途，再看关注度和说明文档，核对支持的操作系统。
- 分清成品安装包和源码。想直接体验应先找可用安装包；若要修改或再次发布，先查看对应开源协议。

## 判断多条网络线路能否为下载提速

<a name="work-7702461223928974646"></a>

**学习场景**　有 Wi-Fi、手机热点等多条接入线路，想知道聚合是否对自己的任务有效时。

- 先看任务会不会发起多个连接。原片演示的 net-merge 用虚拟网卡把不同连接分派给不同线路，单个连接始终走一条线。
- 用同一组并发下载分别测单线和多线，再比较总吞吐量。视频展示的性能数字来自特定并发测试，不能直接套到自家网络。
- 检查是否实际上共用一条上游宽带，以及是否有 VPN 占用虚拟网卡。单线程下载也不能按片中的方式叠加带宽。

**依据**　原片演示画面与屏幕文字
